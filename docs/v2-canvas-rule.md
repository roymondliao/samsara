# V2 條件規範：空白畫布

> 狀態：V2 的第一條規範，先於所有設計內容成立。與其他 V2 文件衝突時，本檔優先。

## 規範

**V2 不是 V1 的優化、修改或重構。V2 從空白畫布開始。** 目標是大破大立、突破格局，不是把 V1 調得更好。

## 空白的範圍

不是所有東西都歸零。界線必須精確，否則這條規範會連公理一起刪掉：

| 層 | 狀態 | 內容 |
|---|---|---|
| 機制層 | **空白** | skills、agents、artifacts、workflow 形狀、目錄結構、validator、CLI、命名 |
| 公理層 | **不空白** | 存在即責任；陰陽雙面；死法先於活法；減法思維；unknown ≠ pass |

公理層不空白是明示的前提（「Samsara 的精神本質不變」）。若連公理一併歸零，產出的東西就不是 Samsara。

## 推導方向

**每一個 V2 設計元素必須從 End 與 Origin 正向推導出來，不得從 V1 差分得出。**

違規句型：

- 「V1 有 X，V2 改成 Y」
- 「刪掉 X」「把 X 收斂成 Y」
- 「V1 已經發明了 X，V2 把它提升到 Z」

合法句型：

- 「要抵達 End 的這一步，必須有 X，因為 ……」

判準：**如果不提 V1 就說不清某個設計決定，那個決定是差分得來的，作廢重推。**

## 巧合允許，來源禁止

若正向推導獨立抵達了 V1 也有的東西，那是收斂驗證，不是污染。被禁止的是**從 V1 推導**，不是**與 V1 重合**。

這條必須寫明，否則會生出反向的太過——為了不像 V1 而拒絕最簡單的方案。那本身就是執著，而且同時違反奧坎剃刀（驗證過的候選裡最簡單者勝出）與減法思維。

## V1 文件的地位改變

`develop.md`、`design.md`、`comparison-mattpocock-skills.md` 從**設計輸入**降為**歷史檔案**。分類見 [`README.md`](./README.md)。

`comparison-mattpocock-skills.md` 要特別小心。它列出的存活原則（成本帳本、user/model invocation 二分、正向陳述、leading words）源頭是 mattpocock 這個外部框架，不是 V1。引用可以，但必須註明來源為外部觀察，且仍須通過正向推導檢驗。不得因為「V1 稽核說它重要」就直接繼承。

## 這條規範自己怎麼靜默失效

- **管不住的部分**：讀過 V1 的人畫的空白畫布會不自覺重現 V1。本規範管得住引用，管不住記憶。
- **可觀察訊號**：設計句子裡出現 V1 的機制名；某個決定講不出 End 依據，只講得出「本來就是這樣」；產出的結構與 V1 同構但換了名字。
- **偵測手段**：每個 V2 設計元素回答一句「這是從哪一步推導出來的？」答不出來的，來源是記憶而非推導。
