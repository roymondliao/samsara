# 02 — 方法：終點—起點回推法

> 方法層。談推導機制，不談實作平台。平台在 [`03-system.md`](./03-system.md)。
> 原則來源見 [`01-philosophy.md`](./01-philosophy.md)，本檔不重述原則。

## 為什麼回推

從原點正推（「這件事該怎麼做？」「還漏了什麼？」）每一步都在現有資訊上開分岔，問題數隨不確定性成長，越問越散。

從終點回推每一步只問「要抵達上一個節點，這一步是不是必要條件」——二元判斷，不是開放式列舉。收斂性來自問句的形狀，不是來自紀律。

## 1. End 與 Origin 是釘死的前提

- **End（終點）**：不問「你想要什麼」，問**如果這件事已經完成，世界有什麼不同、誰會注意到、誰在它不存在時受損**。
- **Origin（起點）**：一份**凍結、有證據佐證**的現狀快照，在建樹之前釘死。
- 兩者一旦釘死，回推過程**不能修改**。

依 [`01-philosophy.md`](./01-philosophy.md) 的白中有黑：**End 宣告本身必須帶自己的失效條件**——這個 End 在什麼條件下是錯的。沒有失效條件的 End 不合法。

## 2. 節點雙面，缺一不合法

一棵樹，不是兩棵。每個節點本身雙面：

```
┌─ 節點 ────────────────────────────────────┐
│ 白面：沒有你，抵達 End 的哪一步做不到？      │  必要性
│ 黑面：你靜默失效時，誰先發現？擴散到哪？     │  死法
└───────────────────────────────────────────┘
        兩面缺一 → 節點不合法，不得展開下一層
```

這讓「硬度」是結構性的，不是一道可以跳過的閘門。**不可能宣告一個只有白面的節點**——這是白中有黑在節點層的落點。

## 3. 樹的文法

節點型別用固定 enum，避免同義詞造成不一致：

- 資訊狀態：`fact` / `decision` / `assumption` / `proposal` / `unknown`
- 結構角色：`End` / `Precondition` / `Origin-leaf`

文法規則：每個 Precondition 只能解到另一個 Precondition、一個 Origin-leaf，或一個 Unknown 葉節點。

### `fact` 必須帶 locator

型別本身不能替內容背書。宣告一個節點是 `fact` 若不需要付出任何東西，`fact` 就只是一個看起來可靠的標籤。

依 [`01-philosophy.md`](./01-philosophy.md) 的責任黑面：

> **`fact` 節點必須附得出 locator。附不出來就不是 `fact`，降型。**

locator 是指向本樹之外、可被第三者重新打開的東西：

| 事實來源 | 合格的 locator |
|---|---|
| 規範、標準文件 | 章節號 ＋ 原文引述 |
| 程式碼、設定檔 | `file:line` |
| 執行結果 | 指令 ＋ 它實際的輸出 |
| 外部網頁 | URL ＋ 取得日期 |

降型的去向由缺什麼決定：

- 有依據但未親自查證 → `assumption`
- 沒有依據，只是這個位置需要一個值 → `unknown`

**降型不是刪除。** 節點留在原位，身分改變，問題被保留。

反例形狀：把一個 `unknown` 放進標著「以下是規範事實」的區塊。標籤替內容背書，之後沒有人會再驗它。**區塊層級的標籤不算 locator**，義務落在每一個斷言上。

推導結論與公理不適用本條——它們本來就不是 `fact`，但必須標明型別，不得混入 `fact` 區塊。

三條借自增量解析器的性質：

- **增量重解析**：新證據出現時只重算受影響的子樹，不整條鏈重來。這解決資訊晚到就得從頭的問題。
- **錯誤恢復**：解不出來的節點插入**顯式** Unknown 葉節點，不中斷整棵樹。unknown 永遠不等於 pass。
- **結構化查詢**：樹建好後可被查詢（「所有仍是 unknown 的葉節點」「critical path 上的 assumption」），不必重讀散文。

## 4. 高度紀律：BFS，不是 DFS

建構順序必須逐層完成，不能一頭栽進某條分支的底部：

```
Level 0  End
Level 1  全貌 / blueprint（End 的宏觀必要前提，粗粒度）
Level 2  範圍 / scope
Level 3+ 細節
```

**當前層沒有完整看過、確認粗粒度上能走到 Origin 之前，不展開下一層。**

「太快掉進細項而沒看到藍圖」正是 DFS 的症狀。額外好處：剪枝可以在 blueprint 層就砍掉整條分支，不必展開到細節才發現路不通。

## 5. 同層候選：奧坎剃刀

同一個前提常有多條候選路徑能滿足。選擇規則見 [`01-philosophy.md`](./01-philosophy.md) 的判準——驗證過的候選裡選最簡單的。

「簡單」是相對於 **Origin 這個具體系統**，不是抽象的最佳實踐。這也是 Origin 必須具體、有證據的另一個理由：只有具體的 Origin，才能讓「對這個系統而言最簡單」成為可判斷的標準。

機制上類似 beam search——每層只留驗證通過的最簡候選往下展開，該候選在下一層驗證失敗才回溯換次簡單的。

## 6. 剪枝：先長滿再剪

逐步貪婪剪（pre-pruning）每一步只看局部，容易卡在局部最優——某節點單獨看必要，長完全樹後可能有更便宜的路徑繞過它。

因此對大型、模糊、高風險的工作採 post-pruning：

- cost = 落實成本 ＋ 風險 ＋ 子樹底下未解 unknown 數量
- value = 對縮短 Origin→End 距離的貢獻
- 存活條件：拿掉這個子樹，Origin 還連不連得到 End。連得到就砍。

這是借推理綱要，不是統計擬合——沒有已完成專案的資料集可以擬合 cost-complexity 的參數。評分是對顯式標準的判斷。

長滿階段的分岔受文法約束（只能長合法節點型別，必須以 Origin-leaf 或 Unknown 收尾），與無邊界發散不同。

**規模閘門**：小型低風險工作用貪婪剪，大型高風險工作才長滿再剪。這決定的是**同層要驗證幾個候選**，永遠不影響要不要看全貌層——全貌層對誰都不能跳。

## 7. 遞迴：終點是尺度相對的

終點沒有絕對層級。project、feature、research、optimize、task 各有自己的終點，差別只在從哪個高度看。北極星指標就是 project 層的 End，不是另一種東西。

因此樹是**自相似**的——層級 N 的一個節點，往下看就是層級 N+1 的 End：

```
層級 N                        往下一層看同一個東西
──────────────────────────────────────────────
Project 的 End    ← 即北極星
  └ 節點：Feature A  ══►  Feature A 的 End
       └ 節點：Task 1  ══►  Task 1 的 End
            └ 節點：缺口小到一步可驗證  →  停止遞迴
```

**Origin 同樣尺度相對，而且是推導出來的，不是重新凍結的：**

- Project Origin = 凍結、有證據的現狀快照
- Feature Origin = Project Origin ＋ 已完成並驗證的兄弟 feature
- Task Origin = Feature Origin ＋ 已完成並驗證的兄弟 task

子層 Origin 由父層 Origin 加上已驗證的完成推導而來，從不憑空另立。這保住第 8 節的硬規則。

**遞迴終止**：Origin 與 End 的缺口小到一步可驗證時停止下降。任務大小因此從結構推導出來，不必另外規定。

一個尺度覆蓋所有工作類型，不需要「先分類工作類型、再查表決定要哪些文件」那一步。深度由缺口決定，不由分類決定。

## 8. 健全性：起點必須連得回去

- 葉節點只有在**可驗證**是凍結 Origin 快照的既有成員時，才算合法終點。用查證確認，不能斷言。
- 連不上時只有兩種誠實結果：
  - **真缺口** → 變成 scope 或 task
  - **與 Origin 矛盾，或需要無界的新能力** → 這就是「該不該做」誠實回答「不該」的時刻
- **不得在推導過程插入新公理。** 節點連不回 Origin 卻把它重新標成起點，等於在證明中途新增前提讓它自圓其說。這代表問題最初的假設就錯了，不是合法出口。
- **剪枝（軟判斷）與起點驗證（硬判斷）必須分開。** 不能讓剪枝把「連不上起點」包裝成「這段被剪掉了」，那是把違規藏進剪枝步驟。
- 若發現凍結的 Origin 快照**本身觀察有誤**（不是憑空另立起點，是對同一起點的原始觀察不準），需要顯式、可見的**重新釘點事件**，整棵樹失效並記錄重建原因。這個區分必須寫進機制，否則會變成可濫用的後門。

## 9. End 講不出來時：先給候選終點

終點本身講不清時（連問題形狀都看不清），硬逼出一個 End，回推鏈就建在假前提上。

解法：先用一個**最小的正推動作**提出候選終點——不必保證正確，只需具體到能被回推鏈檢驗——再讓回推去驗證、剪裁、修正它。

純陰或純陽都會崩壞。回推需要一個小陽的動作才能發動，之後才由陰面剪裁主導。
