# 01 — 理念與精神

> 理念層。只談原則，不談機制。機制在 [`02-method.md`](./02-method.md) 之後。

## 為什麼還需要 external harness

各家都在做 internal harness（Claude Code、Codex、Antigravity、deepseek-harness），社群另有大量 external skill 集合。同時有一派主張：LLM 越強，harness 越不需要，甚至可以讓 LLM 直接從 dataset 自建。

**在沒有規範的前提下讓 LLM 自建 harness，會出現六種失效：**

1. **Overfitting** — 只適配同 domain 的相似資料，對 OOD 資料失效
2. **資料生成是最難的第一步** — 沒有好的合成資料管線就做不起來
3. **為簡單問題設計過多技能**
4. **沒有統一格式規範文檔怎麼寫**（語氣、細節、內容）
5. **技能之間高度相似，違反 DRY**
6. **技能只能單一應用，無法組合**

這六項不是靠更強的模型消失的，它們是**缺少規範**的結果。這是 V2 存在的理由，也是它的可否證條件——見 [`03-system.md`](./03-system.md) 的候選 End 黑面。

## 下一代的兩個焦點

**可組合性**：技能依屬性分類（釐清問題、規劃、實作、審查、產報告、研究），能像元件一樣依任務需求組成處理方式。

目前主流的「LLM 依 description 決定要不要調用」，本質是**遇到問題再找 workaround**，不是先想清楚這個任務該怎麼處理。差別在於前者是被動觸發，後者是先有意圖再取用。

**Domain 創造性**：沒有一套技能能適應所有 domain，所以需要自我改進的能力。但既有嘗試的問題是冗餘、浪費資源、無效的創造與更新——創造沒有門檻。門檻的來源見本檔「不執著」一節。

## 唯一的公理

> **存在即責任，無責任即無存在。**

這條不變，是 [`00-canvas-rule.md`](./00-canvas-rule.md) 明訂的不空白層。

## 責任的兩面：必要性與證據

責任不是一種問法，是兩種。少了任何一面，公理都擋不住東西。

| 面 | 問句 | 誰能回答 | 治什麼 |
|---|---|---|---|
| 白 | 你消失了，什麼會痛？ | 自己，用推理 | 該不該存在 |
| 黑 | 你憑什麼在這裡？證據呢？ | 外部，用指認 | 是不是真的存在 |

**白面是純內部測試，因此擋不住內部生成的內容。** 一個虛構的東西照樣答得出「拿掉我會痛」——因為虛構它的人也在回答這個問題。必要性成立與內容為真是兩件事。

黑面不能在腦子裡回答。它要求指向自身之外：規範的章節號、檔案的 `file:line`、一次跑過的指令輸出。這是唯一抓得到虛構的測試。

**要存在，就要有證據；那份證據就是責任。**

同一條在三個高度：

| 高度 | 證據長什麼樣 |
|---|---|
| 文件層 | 出處連結、章節號、`file:line` |
| 節點層 | 回推鏈上可指認的外部事實（[`02-method.md`](./02-method.md) §3） |
| 執行層 | 檢查者只看得到產物，看不到推理（[`04-skills-subagents.md`](./04-skills-subagents.md)） |

執行層那條因此不是效率設計。同一個 context 裡的檢查者用**推理**評估，繼承製造者的前提；獨立的檢查者只有產物可看，被迫用**證據**評估。隔離買的是證據取代推理。

### 證據決定的不是存不存在，是能以什麼身分存在

「無證據」的直推是刪除。但刪除會把問題連同假答案一起丟掉。

一個附不出出處的斷言，該死的是它 `fact` 的身分，不是它佔的那個位置。降型成 `unknown` 之後，「這裡到底是什麼」這個真問題被保留下來。落點見 [`02-method.md`](./02-method.md) §3。

這是黑中有白：`fact` 死掉之後，`unknown` 葉節點是殘存的那一面。

### 這條自己怎麼太過

推到極致是引用劇場——每句掛註腳，文件不能讀，而且引用到的東西根本不支持那句話。**有引用 ≠ 支持該主張。**

所以證據義務只落在**外部事實**這一型。推導結論的證據是它上游的前提，公理是宣告的。兩者都不需要 locator，但都必須標明自己不是 `fact`。

本節這句公理本身即是宣告，不是 `fact`。

## 公理的層級提升

V2 與 V1 的差別不在公理本身，在它作用的高度。同一句話換一個主詞：

| 層級 | 同一句話的形狀 | 治什麼 |
|---|---|---|
| 程式碼 | 你消失了，什麼東西會痛？ | 死碼、裝飾性功能 |
| 任務 | 你消失了，還能不能抵達 End？ | 該不該做、範圍膨脹 |
| 技能 | 你消失了，什麼任務會做不成？ | 技能過多、彼此重複 |
| 流程步驟 | 你消失了，哪個判斷會漏掉什麼？ | 儀式化步驟、流程肥大 |
| 文件層 | 拿掉這一層，下面推導得出來嗎？ | 文件重複、擁有權不清 |

「技能過多處理簡單問題」與「harness 彼此高度相似」不需要新機制去防。它們是技能層沒有被公理管到的結果。公理提上去，兩者被同一條規則吃掉。

## 太極，不是兩儀

兩儀是兩極並列，中間一條直線。太極是 S 曲線加兩個異色的點——黑白相互滲透，各自含著對方的種子。

**V2 取太極，不取兩儀。** 這個選擇有機制後果，不只是比喻：兩儀讀法會長出兩套並行的東西（兩棵樹、兩套流程、兩份文件），成本加倍且會漂移。太極讀法只有一套，但每個單元本身雙面。

兩條規則：

- **白中有黑**：任何「完成」的宣告必須帶自己的失效條件。說得出「做完長什麼樣」的同一句話裡，要有「這個目標在什麼條件下是錯的」。
- **黑中有白**：任何死法分析必須帶存活面。每條死路要說出「壞掉之後什麼仍然成立、從哪裡接回去」。純記錄傷口而不指認殘存能力，是黑而無白。

節點層的機制落點見 [`02-method.md`](./02-method.md)。

## 物極必反：要偵測兩種太過

界線是曲線，代表比例隨位置流動，而不是「先陽面階段、再陰面階段」。後者是管線思維。每個位置兩面都在，只是主從不同——**沒有任何位置是單面的**。

推到極致，任一面都會生出它的反面：

| 太過 | 症狀 |
|---|---|
| 陽之太過 | 只測 happy path、祈禱式覆蓋率、把 unknown 塞進 success |
| 陰之太過 | 儀式化閘門、流程肥大、跑完流程讓人感到安心 |

第二種特別危險，因為它偽裝成紀律。一套宣稱「感到安心就是走錯方向」的框架，如果跑完它的流程會讓人感到安心，它已經生出了自己的反面。

## 減法與奧坎剃刀

**少即是多。** 但「簡單」不是預設立場，也不是偏好。

跨越多份歷史文件的四種立場——「簡潔不是美德，可追責才是美德」「寫最少的程式」「簡單優先與 production 優先都是偏好」「最簡單最有效就是最好」——用同一條判準收斂：

> **簡單是在可追責這個硬約束下、驗證過的候選裡的勝出者。**

不是複雜不好，是驗證之後這樣最簡單。複雜路徑不被預先淘汰，只在簡單路徑驗證不通時才輪到它。

推論：**V2 的體積必須小於 V1。** 減法先套在框架自己身上，否則「少即是多」只是口號。這條可以寫成可驗證的數字。

## 不執著

不執著單一面向，是太極的另一種說法，也是這個框架名字的來源。

輪迴的成因正是執著。一套叫 Samsara 的框架若建出不可繞過的循環，它就是自己命名的那個困境。V2 要能說出自己的解脫條件——**在什麼情況下，不該用它**。

輪迴的另一半是業力跨越單次生死累積。單次任務的記錄死了就死了，不影響下一輪。真正的輪迴是：新能力不從單一次的念頭誕生，而從跨越多輪累積的證據誕生。這是「domain 創造性」不變成浪費的唯一防線。

## 命名

「向死而驗」精確地命名了單面的立場——守其黑。太極讀法容納兩面，用單面的名字當上位名會自我矛盾。
