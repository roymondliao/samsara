# 90 — 未決問題

> 所有懸而未決的問題集中在此。已決的內容回到它的擁有文件。
> 每題標明**阻塞誰**——沒有阻塞對象的問題不該佔位。

## Q1 — V2 的上位名

「向死而驗」命名的是單面立場（守其黑）。太極讀法容納兩面，用單面的名字當上位名會自我矛盾。

- **選項**：升格既有名／降格為陰面那一極的名字，另取上位名／不取上位名，只留公理
- **阻塞**：[`01-philosophy.md`](./01-philosophy.md) 的收尾
- **不阻塞**：其他所有設計。可以最後再決

## Q2 — V2 的 End 是否接受候選版

[`03-system.md`](./03-system.md) 的候選 End 由一個小陽動作提出，尚未被回推鏈檢驗。

- **阻塞**：整個 Level 1 全貌層的回推。這是目前最上游的未決項
- **要決的**：接受、修改，或換一個候選

## Q3 — validation 任務集怎麼機械生成

流程已定於 [`05-validation.md`](./05-validation.md)，任務從哪裡來未定。

- **要決的**：作用在什麼現成材料上、一次機械操作產出一題的那個操作是什麼、in-dist 與 OOD 的切分依據
- **阻塞**：[`05-validation.md`](./05-validation.md) 的 Phase A，連帶阻塞其後全部
- **注意**：必須是可量產的生成，不是人工挑選。人工挑選解不了保鮮期——base model 一改版就要重取
- **已決，不再是本題**：要納入 OOD（判決規則需要它）、重取觸發時機、流程形狀

## Q4 — 可攜性 vs 隔離性保證

[`04-skills-subagents.md`](./04-skills-subagents.md) 的洞：隔離性的保證只能由會靜默消失的命名空間層提供。

- **選項 A**：接受「可攜但隔離性無法驗證」，在標準層盡量喊出來
- **選項 B**：明講只支援單一 client，用 hook 換取真正的保證，放棄可攜宣稱
- **選項 C**：用 MCP server 做隔離檢查者（MCP 是標準化的，真正可攜），代價是使用者自備 API key、自付成本、自行設定
- **前置**：Q8。三個選項都預設執行層有一個已知落點，目前沒有
- **阻塞**：[`04-skills-subagents.md`](./04-skills-subagents.md) 定案

## Q5 — 遞迴終止條件與雙面粒度下限是不是同一條線

若每一層每個節點都要完整雙面，遞迴到深處會重新膨脹成流程肥大。

- [`02-method.md`](./02-method.md) §7 的終止條件是「缺口小到一步可驗證」
- 雙面要求需要一個粒度下限，否則瑣碎節點也要寫兩面
- **要決的**：兩者是同一條線，還是兩條？若是兩條，要說清楚哪些位置只需單面
- **阻塞**：[`02-method.md`](./02-method.md) 的完整性

## Q6 — 剪枝的 cost/value 標準

[`02-method.md`](./02-method.md) §6 給了形狀，沒給刻度。

- **要決的**：寫成固定 rubric，還是依 work type 彈性
- **阻塞**：無。可以在有實際案例後再定，先用判斷

## Q7 — V2 體積的可驗證數字

[`01-philosophy.md`](./01-philosophy.md) 要求 V2 小於 V1，並說這條可以寫成數字。

- **要決的**：量什麼（skill 數、常駐字數、單一任務產出的 artifact 數），上限訂多少
- **阻塞**：無，但越晚定越容易被違反

## Q8 — 執行層放在哪個目錄

`unknown`。規範 §8 已確認命名空間由 client 擁有，plugin 作者不能自造。證據見 [`03-system.md`](./03-system.md)。

- **要查的**：規範第 11 節全文，確認頂層是否允許出現 client 不認識的目錄（例如 `agents/`）
- **要查的**：Claude Code 是否公布過自己的 agent-plugins 命名空間
- **阻塞**：Q4 的全部三個選項。它們都預設執行層有一個已知落點
- **注意**：本機 plugin 用的是 Claude Code 原生格式，不是 agent-plugins 佈局。兩者是否同一套載入路徑亦未查

## Q8 — rubric 由誰寫、放在哪一層

[`05-validation.md`](./05-validation.md) 要求 rubric 在任何 rollout 存在之前釘死，但沒說它歸誰擁有。

- **風險**：rubric 若與 skill 同層、由同一個 agent 維護，等於把答案交給被評的人。判準會被彎成剛好通過
- **選項**：獨立層由人維護／逐題自動生成但生成者看不到候選／外部化到不可被 skill 觸及的位置
- **阻塞**：[`05-validation.md`](./05-validation.md) 判決的可信度。流程可以先跑，但跑出來的數字在此題定案前不可引用

## Q9 — 雜訊底線與最小可宣稱效果量的刻度

[`05-validation.md`](./05-validation.md) 的 Phase B 給了形狀，沒給數字。

- **要決的**：每題每臂跑幾次、差值多大才算「超出雜訊」、量測不確定性本身怎麼報
- **阻塞**：[`05-validation.md`](./05-validation.md) 的判決規則。沒有這條，「落在雜訊內」判不出來，所有 skill 都會通過
- **注意**：這也決定了 [`03-system.md`](./03-system.md) 那條黑面能不能觸發。若雜訊底線大於 V2 相對 baseline 的整體差距，V2 將永遠無法被否證
