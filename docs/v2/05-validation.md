## 從 End 推出這一層

[`03-system.md`](./03-system.md) 的候選 End 有兩個片語需要這條流程才成立：

- **「組出剛好夠用的處理方式」**——「剛好夠用」預設你知道哪些是需要的。判定不出來就只能全帶著走，那是「過多」不是「剛好」。
- **「留下能讓下一輪更準的證據」**——證據要能改變下一輪，就必須有一個吃證據的程序。沒有這個程序，證據只是紀錄。

依 [`01-philosophy.md`](./01-philosophy.md) 的公理在技能層的形狀（「你消失了，什麼任務會做不成？」）：這個問句目前只能用判斷回答。**用判斷回答的存在責任等於沒有責任**——寫 skill 的人永遠會認為自己的 skill 有用。

[`01-philosophy.md`](./01-philosophy.md) 列的六種失效裡，至少三種（為簡單問題設計過多技能、技能高度相似違反 DRY、技能無法組合）都是這個問句沒有被實測的結果。

## 更新算子只有刪除

模型側靠梯度更新：給一個純量與 credit 分佈，反向傳播自己找該動哪些參數，不需要知道原因。

harness 側沒有這個東西。要改 skill，得先歸因到「哪一份的哪一句造成了這個結果」，而這正是沒有梯度時做不到的事。

**外部觀察**（Inherent Labs, *Training AI Scientists to Replicate Research*, arXiv:2608.13331）：該研究對一個前沿 coding agent 做了 24 代自動 prompt 改寫，每代取 10 題各 8 次 rollout，改寫者能讀到全部歷史 rollout 與評分回饋。結果無實質提升，且改寫後的 prompt **正確指認了失敗模式**。診斷成功，傳遞失敗。

此觀察來自外部框架，不因其存在而自動成立。它在此的作用是排除一條候選路徑：**靠改寫內容來提升 skill，缺乏支持證據**。

因此本流程的出口只有兩個：**留**與**刪**。沒有「改寫後再試」這條邊。這與 [`01-philosophy.md`](./01-philosophy.md) 的減法同源——減法先套在框架自己身上。

## 流程

```
┌─ A. 建 validation set ────────────────── 低頻，先於一切 ─┐
│                                                          │
│   機械生成任務 ──► 切 in-dist / OOD                       │
│         │                                                │
│         └──► 每題生成 rubric ──► 封存                     │
│              （在任何 rollout 存在之前）                   │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ B. 裸跑，釘 Origin ──────────────── 每次 base model 改版 ─┐
│                                                          │
│   無 harness ──► 同一題跑 n 次 ──┬──► baseline 分數        │
│                                 └──► 雜訊底線             │
│                          （決定最小可宣稱效果量與 n）       │
│                          │                               │
│                          └──► 凍結為 Origin 快照          │
└──────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ C. 單一 skill 驗證 ──────────────── 每次 skill 變動觸發 ─┐
│                                                          │
│   只加這一個 skill ──► 跑同一組任務 ──► 同一份 rubric 評分  │
│                              │                           │
│                              ▼                           │
│                        對照 baseline 取差值 ──► 判決       │
└──────────────────────────────────────────────────────────┘
                          │ 留
                          ▼
┌─ D. 組合驗證 ────────────────────────────────────────────┐
│                                                          │
│   通過個別驗證的 skill 全部疊上 ──► 再跑一次同一組任務      │
│                              │                           │
│                              ▼                           │
│              個別有效但組合無增益 → 重複或互相干擾          │
└──────────────────────────────────────────────────────────┘
```

B 的 A 臂同時是 [`03-system.md`](./03-system.md) 那條黑面的判定依據。**baseline 本來就非取不可，取完之後每個 skill 的消融幾乎是免費的。**

D 不可省。個別驗證測不到 [`01-philosophy.md`](./01-philosophy.md) 列的兩個失效——技能高度相似違反 DRY、技能無法組合。

## 判決規則

| in-dist | OOD | 結果 |
|---|---|---|
| 有效 | 有效 | 留 |
| 有效 | 無效 | overfitting，刪 |
| 落在雜訊內 | — | 無責任，刪 |
| 負向 | — | 刪 |

OOD 臂是 in-dist 臂的失效條件，不是額外的嚴格度。只在「寫它時想的那類任務」上有效的 skill，正是 [`01-philosophy.md`](./01-philosophy.md) 列的第一個失效。

## 順序不可交換

1. **rubric 必須在 A 完成，不得在評分時才生成。** 否則判準是看著答案訂的。這與 [`02-method.md`](./02-method.md) §1「End 與 Origin 釘死後不得修改」是同一條紀律。
2. **雜訊底線必須在任何判決之前。** 沒有它，C 的「落在雜訊內」判不出來，於是所有 skill 都會看起來有效。

## 重入觸發

| 事件 | 回到 |
|---|---|
| base model 改版 | B（baseline 與雜訊底線同時失效） |
| 任務集重取 | A |
| skill 新增或修改 | C |
| 任一 skill 被刪 | D（組合變了） |

## 這條流程自己怎麼靜默失效

依 [`01-philosophy.md`](./01-philosophy.md) 的白中有黑，本流程必須帶自己的失效條件。

**管不住的部分**：本流程管得住「skill 有沒有責任」，管不住「量尺對不對」。量尺一旦偏了，整條流程仍然照跑，而且會給出乾淨的數字。

**可觀察訊號**：

- 每一個受測 skill 都通過 → 雜訊底線量得太寬，或 validation set 太貼近寫 skill 的人熟悉的 domain
- 幾乎每一個都被刪 → 雜訊底線量得太嚴，或 rubric 沒抓到 skill 真正作用的維度
- baseline 很久沒重取，而 base model 已改版 → 對照組是舊模型，所有 skill 都會看起來有效
- 通過個別驗證的 skill 數量單調成長 → D 沒有真的跑，或跑了但沒有回收判決

**偵測手段**：對每一個判決回答一句「這個差值有多少來自 skill，多少來自量測」。答不出來的判決，來源是數字而非證據。

第三條訊號最危險，因為它偽裝成成功——見 [`01-philosophy.md`](./01-philosophy.md) 的陰之太過。
